GIT LAW — MASTER
═══════════════════════════════════════════════════════════════════

Trunk-based on `master`. Every commit lands on master and pushes
straight to GitHub, so the local tree, GitHub, your checkout, and
project knowledge always resolve to ONE lineage.

History lives in COMMITS, not branches. Inspect with log / show /
bisect. Tag states worth finding again rather than branching them.

`claude/*` branches are transient review handoffs. This handoff's is
`claude/spawn-0-audit`: merge to master and delete the same day. It is
never lineage.


─── BEFORE REASONING ABOUT ANCESTRY ───

Run this first, every time:

    git rev-parse --is-shallow-repository

Expect `false`, and ~936 commits.

A shallow clone MANUFACTURES ARTIFICIAL ROOTS. It makes `merge-base`
report unrelated histories on a repository that has exactly one. That
misreading cost a full session. If the answer is `true`:

    git fetch --unshallow

— before drawing ANY conclusion about what is or is not merged.

This is the paragraph that was learned rather than assumed. Treat it
as a precondition, not a troubleshooting step.


─── PULL BEFORE ANCHORING ───

Never work from a transcribed branch list or a file snapshot.
Regenerate it.

This applies twice over here: Part A's anchors are themselves
unverified (see DISCIPLINE), and the same standard governs every
ancestry claim in your report. Regenerate, then state.


─── DELETION ───

`--merged master` means deleting the branch loses no commits. It does
NOT mean the branch is unused — check whether a session is live on it
first.

Deleting an UNMERGED branch discards commits. When `git branch -d`
refuses, that refusal is THE TRUTH, not an obstacle. Do not reach for
`-D` to get past it.
