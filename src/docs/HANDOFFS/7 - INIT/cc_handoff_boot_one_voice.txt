HANDOFF A — THE CONFIG OFFSET FIX  (correctness; land first)
───────────────────────────────────────────────────────────────────────────

WHY
  Two targeted config uploads write to literal byte offsets that no longer
  match their fields. The static_assert value and the WriteBuffer literal
  disagree by exactly 32 in both cases; the message strings still carry the
  stale numbers. The build passes, therefore the asserts are true and the
  WRITES ARE WRONG.

    upload_pier_count            writes into  terrain_time    (offset 124)
    upload_placement_patch_count writes into  band_blend_4    (offset 144)

  Invisible today only because terrain_time's rest value is 0. It becomes a
  live bug the moment terrain_time is music-driven. band_blend_4 is already
  wrong: the positive denormal defeats the `blend <= 0 -> skip` sentinel, so
  band 4 is evaluated at every terrain sample for zero contribution.

  The fix DERIVES the offset. A derived offset cannot drift again, which
  makes the static_assert tautological — it goes.
