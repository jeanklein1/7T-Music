# THE BINDING LEDGER

A read-only census of every declaration that spends a WebGPU slot, and of
what the program can actually reach through it. Generated by
`tools/binding_ledger.py`; do not hand-edit — re-run it.

**One row per `(bind group layout, entry index)`, not per buffer.** The
registry is one constant per SITE: the same buffer wears several names
because each name is one `(group, slot)`. A buffer-keyed census would
merge rows the API charges separately.

inputs — not `HEAD`, which moves when this file is committed. The content

**Determinism is asserted at byte level, not by comparing two local runs.**
Two runs on one host are byte-identical even if the write is
host-translated, because both are translated the same way — Python's text
mode rewrites `\n` to the platform terminator unless `newline` is pinned. So
the writer pins `encoding="utf-8", newline="\n"` (witness `G2-eol`), and a
binary read-back after every write asserts LF-only, no BOM, exactly one
trailing newline. A violation stops the run instead of shipping a file that
breaks the L1 encoding law on one platform and not another.

### The law this serves

A slot is charged **once per stage named in `visibility`**, whether or not
that stage can reach the binding. Bind **groups do not partition the
budget** — every bind group layout in a pipeline layout is concatenated,
then checked. **Bytes and slots are unrelated currencies.** Core defaults,
per shader stage: uniform 12 · storage 8 · sampled 16 · samplers 16 ·
storage textures 4. Per pipeline layout: bind groups 4, dynamic-offset
uniform 8, dynamic-offset storage 4. Per binding: uniform 65536 B, storage
134217728 B. Uniform bindings also need 256 B offset alignment, which
matters only where a binding is a window onto a shared buffer.

### Findings — reported, not acted on

**1. The binding surface does not vary with the demo column.** No bind group layout creation site sits inside a `if constexpr (ROSTER.…)` gate — all 29 are created unconditionally. So slot pressure exists for pipelines a given build never creates: the PIPELINE set is ROSTER-gated (38 of 59 pipelines carry a gate), the LAYOUT set is not.

**2. No dead surface in the shader.** All 96 module-scope declarations are reached by at least one of the 65 entry points.

**3. Zero dynamic-offset bindings.** `hasDynamicOffset` is never set
anywhere in `state.hpp`; the two dynamic-offset limits stand at 0/8
and 0/4 program-wide. Computed each run; witness `0d-1` is the gate
this figure answers to.

**4. The tightest row is not where the handoff expected it (as of BUDGET_1).** BUDGET_0's
handoff expected the main render family's VERTEX stage at storage 8/8. It
reads **storage 3 of 8**. The tightest row in the program is
**Update Player Agent (0D, 1 thread) / C at uniform 11 of 12** — over the concatenated groups `worldLayout_` + `frameCLayout_` + `agentsStateLayout_` + `agentsTexturesLayout_`,
shared by `update_player_agent`, `update_other_agents`, `update_sphere`, `update_cube`.
`world.wgsl`'s COMPILER FLOOR banner carries the standing demotion rule for
the room family, which stands at 0 of 8 storage. And
its `actual` column reads 11 too: **an A1 sweep buys nothing on the one row
with no margin.**

The handoff asked which comment has outlived its referent if the render
family did not reproduce 8/8. Three have, to different degrees. Each is
quoted only because it is still present in `state.hpp` today:


**5. One correction to the handoff's A2 rule, and the ledger follows the
spec (as of BUDGET_1).** The handoff states that in the uniform address space
`array<f32, N>` *and* `array<vec3<f32>, N>` are illegal. The first is
right; the second is not. The rule is that the array's **element stride**
— `roundUp(AlignOf(E), SizeOf(E))` — must be a multiple of 16.
`AlignOf(vec3<f32>)` is 16, so the stride is `roundUp(16, 12)` = 16 and the
array is legal; it merely wastes 4 B per element. `array<vec2<f32>, N>`
(stride 8) *is* illegal, as is any scalar element. A type's own alignment
being under 16 is not a blocker either: `array<AgentBehaviorParams, 10>`
has `AlignOf` 4 and stride 32, and the program binds it as a uniform
today. Witness `0b-5` is the guard — the predicate clears all 27
declarations the program already places in uniform.

**6. The C6 note on `g2::field_head_poses` did not cost an element type (as of BUDGET_1).**
The handoff attributes an element-type widening to that demotion. At
`ecfbc32`, the commit that introduced the binding, both `g0:122
head_poses` and `g2:2 field_head_poses` already read
`array<vec4<f32>, 400>`. The demotion changed the address space over an
element type that was already vec4-strided. Table C still records the
required element type per A2 row, because for other candidates it is a
real cost — it just was not one there.

**7. A4 is empty, so BUDGET_1 is the A1 sweep alone (as of BUDGET_1).** Every one of the
31 `var<storage, read_write>` declarations is written by at least one entry
point that reaches it. No binding claims write access it never exercises.

**8. The room family cannot be fused, and the reason is mechanical (as of BUDGET_1).**
All 12 ordered pairs among `update_player_agent`, `update_other_agents`,
`update_sphere` and `update_cube` carry a RAW hazard — `agent_state`
between the agent kernels, `floating_entities` between the floater
kernels, and `field_forces` across the divide. Fusing deletes the implicit
inter-dispatch barrier that makes the ordering correct, and WGSL has no
device-wide barrier to put back. Table E has the pairs.

**8b. The program has ZERO fusable pairs, and the ordered table alone
does not say so (as of BUDGET_1).** A fused kernel has no ordering — its threads run
concurrently inside one dispatch — so fusability needs the UNORDERED
closure, not the ordered hazard list. Of 38 unordered fusion-eligible
pairs, **16 survive RAW in both directions**, and both couple an on-demand
pass with a per-frame one — fusing either would change WHEN work runs, not
just how it is dispatched. RAW-clean is necessary, not sufficient: cadence
is the second gate and it lives in the dispatch schedule, not the shader.

**9. The vertex-buffer candidates are not the ones that were proposed (as of BUDGET_1; the eligible row spent by DOMESDAY_0 B3).**
`visible_patch_indices` WAS eligible — one site, `[patch_id]`, sequential in
`instance_index`, stride 4 B — and DOMESDAY_0 B3 spent that row: the
visible list now arrives in `patch_terrain_vs` as an instance-step vertex
attribute (`@location(0) visible_id`) and the binding is retired.
`patch_instances` remains BLOCKED, now by the attribute join inside ONE
entry point: `patch_terrain_vs` reads it sequentially on the direct path
and through the `visible_id` attribute under the `USE_PATCH_INDIRECTION`
override. `render_ring_xforms` is blocked
at `builtin_derived(vertex)` — segment arithmetic, many vertices per ring,
and its pipeline draws with instanceCount 1 besides. A third candidate
nobody named: `render_orb_state`, eligible on access pattern AND drawn
instanced, and a runtime-sized array — the class A2 cannot touch.

*TETRIS ORB_V took that third candidate; DOMESDAY_0 B3 took the first.*
The two blocked rows stay blocked for the same reasons as at BUDGET_1.

**10. The single-thread count is three numbers, not one (as of BUDGET_1).** 13 entry points
declare `@workgroup_size(1)`; 8 dispatches issue one workgroup; the
intersection is 7. `update_other_agents` dispatches ONE workgroup at
`@workgroup_size(32)` — which is exactly the shape the kernel-split banner
prices at 48 seconds of FXC.

**11. 81 defended sites.** Table H marks where the program already paid to
learn something. It cites and does not quote, so it cannot go stale against
the prose it points at.

**12. The census corrected its own instrument, and the lesson is the
campaign's (as of BUDGET_1; the control re-keyed at LOOM_2).** BUDGET_1 removed two layout seats and renumbered the
survivors, and `W4-2` failed — not because the sweep was wrong, and not
because the instrument stopped finding the defended prose. It found all
81 sites with identical trigger sets. What broke was the CONTROL'S KEY:
it named two defended sites `Render Entity Layout entries[16]` and
`entries[17]`, and a campaign whose job is removing layout entries
renumbers the survivors.

**An index is a position; a binding is an identity.** The control was
itself a reference that outlived its referent — precisely what Table H
says about line numbers, one layer up and pointed at the instrument. It is
now keyed by the binding each seat carries, `bind::g2::agent_tier_gains`
and `bind::g2::agent_figure_profiles` in the Scene State Layout (their
LOOM_2 home; the identity followed the seats through the recut), which
survive renumbering. The displayed `entries[N]` column stays, because it
is regenerated every run and a reader wants it.

Recorded here as a finding rather than only in a commit body, because a
positive control that can be made to pass by whoever it is testing is not
a control. The re-key was authorised before the run that had to pass it.

## Table B — the stage budget

One row per `(pipeline, stage)`, counted across **all** the pipeline's
group layouts concatenated. Each cell reads `declared / actual / reached`
against the Core limit in the header.

- **declared** — counted against `vis_declared`. *This is what the API
  charges.* Every one of these must fit, and the gate above says they do.
- **actual** — counted against `vis_actual`: the same rows, minus those no
  reachable code touches through this layout in any pipeline that binds
  it. This is what the budget would read after an A1 sweep. **The
  difference between these two columns is the entire prize of BUDGET_1.**
- **reached** — counted against what *this pipeline's* stage actually
  touches. A derived third column, narrower than `actual`, because a
  visibility mask is shared by every pipeline binding the layout and can
  only be trimmed to the union. It bounds what any per-pipeline split
  could ever buy.

## Table F — vertex-buffer eligibility

Vertex buffers are the one wallet that can absorb a RUNTIME-SIZED ARRAY,
which is the class A2 structurally cannot touch. Eligibility is decided by
ACCESS PATTERN, not type: every access in every entry point that reaches
the binding must be `builtin_sequential` on the same builtin, and the
element stride must fit `maxVertexBufferArrayStride` (2048 B).

**An `override` gate does not rescue a mixed classification.** An override
selects a branch inside ONE entry point, and one entry point has ONE
signature. A binding read both sequentially and indirected under an
override is blocked; moving it needs a second entry point, which is
another FXC compile. That cost is in the row, not omitted from it.

A pipeline drawn with `instanceCount` 1 cannot host an instance-step
buffer whatever its access pattern says — Table G carries the counts.

An `override gate` on an ELIGIBLE row is not a blocker but is a cost:
the access happens in only one pipeline variant, and the variants share
the entry point and therefore the vertex signature. Moving such a binding
obliges the sibling variant to bind the slot too, or splits the entry
point. `visible_patch_indices` was the row this applied to — DOMESDAY_0
B3 moved it and paid exactly that cost: the direct variant binds the
slot and leaves the attribute unread.

### What an eligible move costs

Eligibility is not freeness. A vertex buffer removes a bind-group binding
and spends vertex-buffer and vertex-attribute slots instead, and the
underlying buffer needs `BufferUsage::Vertex` alongside `Storage` — the
same class of program edit that A2 needs `BufferUsage::Uniform` for, and
the reason neither is free. Attribute count assumes vec4 packing,
`ceil(stride / 16)`.

| symbol | pipelines reaching it | vertex buffers | vertex attributes | buffer usage |
|---|---|---|---|---|

Program-wide today: **2 of 8** vertex buffers, **13 of 16** vertex
attributes. NO eligible move remains: every Table F candidate above is
blocked, so these maxima are where the program stands rather than a
floor under a reserve.

`render_orb_state` is absent from the table above because TETRIS ORB_V
TOOK the move. The orb state reaches `orb_vs` through an instance-step
vertex buffer — one attribute per `OrbState` field, offsets mirroring the
struct — and the binding-400 seat is gone from the Render Entity Layout,
from `world.wgsl` and from the registry, where the trio of names on that
buffer is now the duo `orb_state` / `orb_state_ro`. The Orb Sky Layer is
the pipeline that paid: it carries the program's vertex-attribute maximum
of 13 now, where the arch family's 4 stood before.
