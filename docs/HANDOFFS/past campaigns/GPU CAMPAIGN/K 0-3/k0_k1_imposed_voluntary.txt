WHY THIS BATCH (state it in the log; it reframes every gate):
CONTACT_2's impulses are applied AFTER `agent_post_step`, whose order
is drag → speed cap → steering → POSITION INTEGRATION → ground snap.
So an imposed impulse (a) moves nothing the frame it is applied —
integration already ran — and (b) meets the drag + speed cap at the
top of the NEXT frame before integration. A worker fleeing a player at
15 wu/s asks for 18 and receives its voluntary cap (4.5), one frame
late. THE CAP IS THE ENEMY OF ALL IMPOSED MOTION — shove and flee
alike. The design error is the handoff's, not the execution's: "apply
after the cap" is, in a loop, "apply before the next cap."

THE LAW THIS BATCH INSTALLS: **the speed cap governs INTENT, not
imposition.** A body chooses how fast to walk; it does not choose how
fast it is displaced by another body.

GATE PHILOSOPHY (changed, deliberately): this is a TUNING batch.
Terrain/pixel rest identity still gates. Movable-body behavior is
MEANT to change — do not defend the old feel.

One surgical move: integration and snap leave `agent_post_step` and
happen AFTER the contact gather, so imposed motion lands the same frame

COMMIT [K1a] — split post_step
1. CLASS B — `agent_post_step`: REMOVE its tail (position integration,
   ground snap, heading-from-velocity) and place that tail VERBATIM
   into a new function directly below:
     fn agent_settle(agent_in: AgentState) -> AgentState { ...tail... }
   `agent_post_step` keeps drag, speed cap, and the C2b steering block
   and returns the agent with velocity shaped but position untouched.
   Banner rewrite (both functions), stating the law:
     "agent_post_step — VELOCITY shaping only (drag, cap, steering).
      Integration + ground snap + heading moved to agent_settle, which
      the KERNEL calls AFTER the contact gather: the speed cap governs
      INTENT, not imposition — a body does not choose how fast it is
      displaced by another body (CONTACT_3)."
   Behaviors' ten `return agent_post_step(...)` call sites are
   UNCHANGED (same name, same params) — only the contract narrowed.
2. CLASS B — `update_other_agents`: after the existing contact/flee
   gather and BEFORE the eviction block, insert
     a = agent_settle(a);
   (use the kernel's own variable spelling). Order is now:
   behavior (shaped) → gather (imposed) → settle (integrate + snap) →
   evict. Comment the seam with the law line.
3. FXC NOTE for the log: the ground chain moves from ~10 inlined
   call sites (one per behavior) to ONE. This should REDUCE the
   kernel's compile cost, not raise it — report the witness timing
   delta if visible.
4. DISCLOSE in the log: the gather now reads a pre-settle `pos_y`
   (last frame's snapped height) for the 3D gate. dy changes slowly;
   a one-frame-stale y is immaterial to a soft field. Named, accepted.

WORKED EXAMPLE (put this in the commit message — the new handoff law):
  worker (cap 4.5), player approaching at 15 wu/s, gain 1.2, dt 1/60.
  gather: v_ap = 15 → demand 18; vel·dir = 0 → deficit 18 → vel += 18·esc.
  settle: displacement = 18/60 = 0.30 wu this frame (player moves 0.25).
  next frame: drag+cap trim vel to 4.5 → gather sees vel·dir = 4.5 →
  deficit 13.5 → tops back up to 18. Sustained escape, self-correcting,
  no runaway momentum. BEFORE this commit the same case produced 4.5
  wu/s, one frame late.
